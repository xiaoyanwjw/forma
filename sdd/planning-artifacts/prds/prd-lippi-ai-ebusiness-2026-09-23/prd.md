# PRD：电商选品与 listing 自助生成（积分制）

*曾用工作名「AI 员工落地陪跑」。近端产品形态为自助工具，非人工陪跑服务。*

## 0. 文档用途

供产品决策、后续 UX / 架构 / 拆故事使用。能力用稳定编号 FR。技术选型（具体大模型、框架）不在本文展开，见待决项与日后 addendum。

## 1. 愿景

让淘宝 / 闲鱼 / 拼多多上的一人店主，用网页自己点几下，就能拿到「可以卖什么」的清单（带理由），以及一套能上架的主图 + 详情素材——少做重复劳动，不承诺一定卖得出去。小程序在网页之后补。

**终局：** 选品 → 设计 → 询盘 → 客服 → 物流 → 收款尽量自动化。  
**近 3–6 个月：** 只做选品 + listing 生成；积分订阅变现；对准主业月入约 1–2 万（目标感，非承诺）。

## 2. 目标用户

### 2.1 要完成的工作
- 不知道卖什么，需要一份带理由的候选清单
- 有品或选定品后，需要主图和详情页文案/展示草稿，好上架
- 希望自己操作、按次消耗，而不是雇人或定制外包

### 2.2 近端优先客群
- 刚做电商的一人店
- 已有店但不擅长选品的人
- 平台语境：淘宝、闲鱼、拼多多（出海后置）

### 2.3 近端非目标
- 深度定制项目需求方
- 需要人工全托代运营 / 陪跑交付的客户（近端不做主交付）
- 暂不按 GMV/团队规模硬性排除；若免费额度被刷，再补规则

### 2.4 关键旅程（轻量）

**UJ-1. 小陈：从「不知道卖啥」到拿到 10 个候选品**  
一人淘宝店主小陈注册进入工具 → 选品类/简单条件 → 消耗积分生成清单 → 看到约 10 个候选及理由 → 决定是否再生成或进入 listing。

**UJ-2. 小陈：从候选品到一套能上架的素材**  
选定或输入一个品 → 消耗积分生成主图 + 详情文案/展示 → 下载或复制去店铺上架 → 若不满意可重试（再扣分）。

**UJ-3. 小陈：积分用完后升级**  
免费额度用尽 → 看到 Pro/Plus 与积分差异 → 订阅后积分按月重置继续用。

## 3. 术语表

| 术语 | 含义 |
|---|---|
| 选品清单 | 一次生成得到的「可以卖什么」列表，含理由；目标约 10 条候选 |
| Listing 套装 | 一次生成得到的主图 + 详情页文案与展示说明，用于上架 |
| 积分 | 计量单位；指定生成动作消耗积分 |
| 套餐 | 免费版 / Pro / Plus；差异为每月积分额度 |
| 品类模板 | 按品类（如家居、电子）约束生成风格与字段的模板；三档均可使用已上线模板 |
| 积分月重置 | 订阅周期到点按档位重新发放；**未用完清零** |

## 4. 功能需求

### 4.1 账号与进入

**说明：** v1 以 **网页** 为主；小程序后续迭代。

#### FR-1：注册与登录
用户可以创建账号并登录后使用生成能力。

**可验证：**
- 未登录不能消耗积分完成生成
- 登录态下能看到当前剩余积分与套餐档

#### FR-2：套餐与积分展示
用户可以查看当前套餐（免费 / Pro / Plus）、本月剩余积分、下次重置时间。

### 4.2 积分与订阅

#### FR-3：按动作扣积分
系统在成功产出可用结果时扣积分：
- 生成一份选品清单 → 扣 **1** 积分
- 生成一套 Listing 套装 → 扣 **1** 积分

**可验证：**
- 积分不足时不能开始生成，并提示升级或等待重置
- 生成失败且未产出可用结果时不扣分或自动退回（须实现并测通）

#### FR-4：三档月积分额度
- 免费版：每月 20 积分  
- Pro：每月 200 积分  
- Plus：每月 600 积分  

#### FR-5：积分按月重置且清零
到订阅周期节点，按当前档位重新发放积分；上月剩余 **清零不结转**。

#### FR-6：订阅升级
用户可以从免费升级到 Pro 或 Plus。**月费数字待定**（按模型成本倒推）。

### 4.3 选品生成

#### FR-7：生成选品清单
用户可选择品类模板（及必要的简单输入）后生成选品清单。实现 UJ-1。

**可验证：**
- 一次成功生成给出约 **10** 个候选（允许 8–12，产品内写清）
- 每个候选含 **可卖理由**（至少一句可读说明）
- 结果可在历史中再次查看（FR-12）

#### FR-8：品类模板选用
用户可以选用不同品类模板（例如家居类、电子类）再生成。  
**规则：** 免费 / Pro / Plus **均可使用全部已上线模板**；新品类由运营排期上新，不按套餐解锁。

### 4.4 Listing 生成

#### FR-9：生成 Listing 套装
用户基于某个候选或自填商品信息，生成主图 + 详情页文案与展示说明。实现 UJ-2。

**可验证：**
- 产出物包含：主图（或主图方案）、详情文案、详情如何展示的说明
- **不是** 实体包装/纸箱设计
- v1 风格为 **国内通用** 一种，不做淘宝/闲鱼/拼多多三套强适配

#### FR-10：导出或复制
用户可以将 Listing 套装下载图片 / 复制文案，便于去店铺上架。

### 4.5 质量与反馈

#### FR-11：重试与反馈
用户可以对不满意的结果发起重试（再次扣分）或提交简短「质量差」反馈。

### 4.6 历史记录

#### FR-12：生成历史
用户可以查看本人近 **60 天**内的选品清单与 Listing 套装。

### 4.7 明确不做（近端）

- 询盘 / 客服 / 物流 / 收款自动化  
- 出海平台深度适配（Shopify / 亚马逊等）  
- 人工陪跑、代运营、效果对赌为主交付  
- 承诺销售额或 GMV  
- v1 小程序（后置）  
- v1 三平台分风格 listing  

## 5. 非功能需求（NFR）

#### NFR-1：可用质量底线
选品理由可读、无明显违规胡编；Listing 文案可粘贴修改后上架。抽检比例待定。

#### NFR-2：成本可控
定价前须能统计单次选品 / 单次 Listing 的模型成本；售价须覆盖成本并留毛利。

#### NFR-3：失败可理解
失败时给人话原因（额度不足 / 服务繁忙 / 输入不完整）。

#### NFR-4：基础合规
避免明显违禁宣传；协议声明 AI 生成须人工复核后再上架。

#### NFR-5：防刷（轻量）
v1：登录 + 异常频率限制即可。

## 6. 成功指标

| 类型 | 指标 |
|---|---|
| 生意 | 付费用户数；月收入（目标感 1–2 万/月） |
| 用户价值 | 选品约 10 候选；可上架 Listing 套装 |
| 反指标 | 不以「只注册不生成」为成功；不承诺 GMV |

## 7. 风险

| 风险 | 应对方向 |
|---|---|
| 生成质量差被骂 | FR-11、NFR-1、协议要求人工复核 |
| 没人来用 | 获客与冷启动需单列运营计划（功能外，但必须有人负责） |
| 模型成本倒挂 | NFR-2；定价前实测；必要时提高单次扣分或降免费额度 |

## 9. 已确认决策摘要

- 准主业；Coaching；愿景+功能入口  
- 终局全链路；近端仅选品 + listing；自助网页；积分订阅  
- 客户：一人店 / 不会选品；平台先国内三家，出海后置  
- 套餐仅积分差：20 / 200 / 600；月末清零  
- 选品与 Listing **均扣 1 积分**  
- 模板三档通用 + 运营上新；国内通用风格；小程序后置
