## 3. 可补充 Skill（候选项，未立项）

原则：和上面三个**不重复**；仍是「跑完有一页可带走」；产品侧偏「判断/扫描」，前沿侧偏「原文/材料」。

### 产品雷达 · 可补

| 候选 | 和早报/竞品的差别 | 为什么实用 |
|------|-------------------|------------|
| **发布会/发布页拆解** | 早报是多条扫描；这个是**一场发布**深拆 | 发布会后高频需求：新在哪、对谁有意义 |
| **品类地图** | 竞品是点对点；这个是**赛道俯瞰** | 「这个品类有谁、怎么分层」一页纸 |
| **评价炼金（科技）** | 不比官方卖点，炼**用户口碑** | 和应用商店/社区评价结合时很香；注意来源粘贴 |
| **定价与套餐对照** | 竞品偏定位话术；这个偏**买哪档** | SaaS/API 档位对照表，决策快 |

暂不补（易飘或和近端重叠）：无出处热点榜、绝对「值不值买」投资结论。

### 科技前沿 · 可补

| 候选 | 和链接速读的差别 | 为什么实用 |
|------|------------------|----------|
| **多链合读** | 速读是 1 链；这个是 **2～3 链合成一页** | 同一主题几篇官方文/博客，合成对照 |
| **长文精读卡** | 速读偏「快看懂」；这个偏**章节级要点 + 摘句** | 白皮书、长 RFC、长博客 |
| **材料对照** | 不是摘要一篇，而是**两份材料差异** | 新旧版本文档、两家技术方案对照 |
| **播客/纪要速读** | 输入是粘贴转录，不是网页链接 | 会议/播客听完没纪要时 |

暂不补：自动写代码、无原文编造摘要。

## 6. 市面参考（2026-10 调研）

目的：核对「产品雷达 / 科技前沿」拆法是否站得住；只学信息架构与输出纪律，不抄企业 CI 全套。

### 6.1 和近端 Skill 的对照

| 我们 | 市面常见叫法 | 代表产品 | 他们怎么切 |
|------|----------------|----------|------------|
| **产品早报** | Daily digest / Product radar / Briefing | [ToolRadarHQ](https://toolradarhq.com/)、[Launly](https://launly.com/)、开源 [AI Product Radar](https://github.com/BENZEMA216/ai-product-radar)、[OnAirToday](https://onairtoday.com/) | 「今天值得看的 3～7 条」；常按新品 / 更新 / 融资 / 工具分栏，不是一篇长文 |
| **竞品分析** | Competitive intelligence / Teardown | [Urlcomp](https://www.urlcomp.com/)（粘贴 URL → 分层报告）、[Discera](https://discera.ai/)、企业向 Klue / Crayon | 入口常是对手 URL / 对手列表；输出 battlecard、功能对照、变更监控 |
| **链接速读** | Link / article summarizer | [Cubox](https://cubox.cc/) AI Insight、[BibiGPT](https://bibigpt.co/) Article Summarizer、[Overchat Link Summarizer](https://overchat.ai/text/link-summarizer)、[Brevio](https://www.universalsummarizer.com/)、[Glasp](https://glasp.co/ai-summary)、Recall | **一篇材料 → 摘要 / 要点 / 追问**；偏阅读，不偏销售 battlecard |

结论：市面普遍把「扫市场」和「读一篇」拆开；我们两张卡与此对齐。

### 6.2 值得抄的信息架构

**早报类 → 产品早报**

- 条数要少（约 3～7），每条固定字段：**是什么 / 给谁 / 为什么现在看 / 出处**。
- ToolRadar、Launly 强调「几分钟读完」，不是情报库。
- OnAirToday 把 Daily Briefing 与 Product Radar（工具上新）分栏——近端可合成一个 Skill，但输出里最好能区分「动态」vs「新品」。

**竞品类 → 竞品分析（已定：follow Urlcomp）**

- **主路径 = Urlcomp：** 贴 **1** 个公网产品 URL → 分层报告；每字段 Found / Inferred / Not Public；对手列表是报告内一层，不是用户先交 2～N 链。
- Discera / Klue / Crayon 偏持续监控 + battlecard，近端不学成企业 CI；可后置「监控刷新」。
- 国内秘塔 / Kimi「深度研究」可参考「要结构化报告」，但纪律上仍以 Urlcomp 三态标签为准。

**速读类 → 链接速读**

- Cubox AI 常拆成：速读摘要 / 关键问答 / 自动划线——近端「一页摘要」够用；加厚时可参考「摘要 + 几个关键问题」。
- Brevio 分「每日多源合读」vs「单次 URL 速读」——正好对应产品早报 vs 链接速读的边界。
- 秘塔 / Perplexity 是搜索引擎，不是场景 Skill；可学「答案带引用」，不做通用搜索。

### 6.3 市面常见工作类型（与画廊对齐）

```text
监控扫描（Briefing / Radar）        → 产品雷达 · 产品早报
单品拆解（URL Teardown / Urlcomp） → 产品雷达 · 竞品分析
单篇消化（Summarize / Quick Read） → 科技前沿 · 链接速读
```

企业情报（如 AlphaSense：研报/财报库）与 Forma 个人/小团队工作台不是一路，近端忽略。

### 6.4 市面有、近端先不做

| 市面常见加项 | 谁在做 | 对 Forma |
|--------------|--------|----------|
| 对手网站变更监控 | Discera、Crayon | 要爬虫+日程，后置 |
| 销售 Battlecard | Klue、Crayon | 偏 B2B 销售，场景弱相关 |
| 多源每日合读 | Brevio | 可作产品早报增强，不单开场景卡 |
| 视频/播客摘要 | BibiGPT、Recall、Cubox | 可作科技前沿后置 Skill（见 §3） |
| 知识库沉淀 | Recall、Cubox、Glasp | 与「跑完 Computer 一页纸」形态不同 |

### 6.5 落到近端 Skill 的三条原则

1. **产品早报**：学 ToolRadar / Launly——短条目 + 出处；不做 AlphaSense 式情报门户。  
2. **竞品分析**：完整 follow Urlcomp 主逻辑（见 §7）——单 URL 拆解 + 三态标签；不做多链对照主路径、不做 Klue 监控套件。  
3. **链接速读**：学 Cubox Quick Read——一篇进、一页出；与早报严格分开（早报多条扫描，速读单源深读）。

## 7. 竞品分析 · Urlcomp 对齐（2026-10-07 拍板）

参考：[Urlcomp](https://www.urlcomp.com/)（原 rivallens.net 产品叙事）。

### 7.1 用户怎么用

| 项 | 近端约定 |
|----|----------|
| 主输入 | **1 个**公网产品首页 URL |
| 可选 | 一句「我关心…」（定价 / 适不适合小团队等） |
| 兜底 | 抓页失败 → 请粘贴官网可见正文；**禁止**无材料编 Found |
| 不做主路径 | 用户提交 2～N 个链接做并排对照表（可后置为「再拆第二个 URL」或手递第二次跑） |

### 7.2 引擎逻辑（学什么 / 裁什么）

**学：**

1. **先取证再推理**：公开页 / 文档抽事实，再写各层。  
2. **字段三态**：Found（公开可核对）/ Inferred（推断 + 理由）/ Not Public（空着，不装成事实）。  
3. **固定分层骨架**（输出合同），不是自由聊天。  
4. **「同类对手」是报告内一层**：从本品定位/公开提及推断 若干对手，**默认 Inferred**，除非页上明文列出。  
5. Computer 可带走（对齐其 Markdown/PDF 导出心智）。

**近端裁掉（后置）：**

- Urlcomp 全量 10 层 + 8 Agent 并行（过重）  
- 估 MRR / CAC 等强推断财务（易伤信任；若要写必须 Inferred 且少而慎）  
- Similarweb 流量盘、日监控、多对手 Radar 订阅  

### 7.3 近端建议输出层（精简版骨架）

不必 10 层，建议先 4～5 块写进 `references/output.md`：

| 层 | 内容 | 状态纪律 |
|----|------|----------|
| 产品快照 | 定位、人群、公开定价信号、一句话 | 能摘到 → Found；否则 Not Public |
| 为何有人付费 / 差异点 | 卖点、切换成本、护城河表述 | 以页上原话为主 |
| 商业与套餐信号 | 公开价档；无则 Not Public | 禁止臆造标价 |
| 增长 / 公开信号 | 仅当页上或已接结构化源有证据 | 无源则整层可省略或 Not Public |
| 同类对手速览 | 5～8 个名字级对照（极短） | **默认 Inferred**；有原文列举则 Found |

整页仍是 **一份 Computer 文档**，不是多 Tab 情报站。

### 7.4 取数（与链接速读的分工）

```text
1 URL
  → fetch_web_page（Apify WCC）×1，可选 pricing 链再 ×1（有界）
  → excerpt_chunks
  → 主模型按 §7.3 骨架填字段 + 三态
  → render_view → 结算
```

与 **链接速读** 共用抓页/摘句工具；Skill 正文与 output 合同不同（情报层 vs 文章摘要）。

### 7.5 和「多链对照」的关系

- **近端：** Urlcomp 单品拆解。  
- **若用户要两家硬比：** 跑两次竞品分析，或后置「对照」Skill；不挡单 URL 主路径。

## 8. 产品早报 · 实现咬合（2026-10-08）

参考心智：ToolRadar / Launly「今天几条值得跟」；**非** Urlcomp 单品拆解。

**设计 / 计划：**  
`docs/superpowers/specs/2026-10-08-tech-briefing-design.md`  
`docs/superpowers/plans/2026-10-08-tech-briefing.md`

### 8.1 用户怎么用

| 项 | 近端约定 |
|----|----------|
| 场景 / 胶囊 | 仍在 **产品雷达**；第二颗胶囊 **产品早报**（默认胶囊保持竞品分析） |
| 主输入 | **关注域 / 主题**（短句即可）；可选近 N 天 |
| 兜底 | 粘贴 Newsletter / 列表正文 → 跳过列表 Actor |
| 不做主路径 | 多源合订、定时推送、无出处热点榜、估值财务 |

### 8.2 引擎逻辑（学什么 / 裁什么）

**学：** 候选列表 → 过滤/去重/截断 → **默认深挖 1 条详情** → 短条目（是什么 / 为什么值得跟 / 出处）→ 一页 Computer。

**近端裁掉：** 第二数据源（HN/RSS 等）、向量聚类、日监控订阅、列表**全员**逐个深挖。

### 8.3 取数

```text
关注域（或 paste）
  → search_product_launches（Apify · Product Hunt 单 Actor）→ candidates[]
  → 关键词过滤 + URL/标题去重 + 截断（供模型再筛，上限约 12）
  → （默认）拟入选第 1 条 fetch_web_page ×1；deepFetch=0 可关
  → 主模型写 items[3..7]（有依据才写；禁止无候选编造）
  → render_view → persistAs=tech_briefing → settle
```

| 钉死项 | 值 |
|--------|-----|
| Skill id | `tech-briefing` |
| 主源 | **仅 Product Hunt**（actorId 可配置） |
| 条数 | 目标 **3～7** |
| 深挖 | **`deepFetch` 默认 1**；近端上限 1；0=关 |
| persistAs | `tech_briefing` |
| pack | `requiredSkills: [tech-competitor, tech-briefing]`；`defaultSkill: tech-competitor` |

### 8.4 和竞品 / 链接速读的分工

| | 产品早报 | 竞品分析 | 链接速读 |
|--|----------|----------|----------|
| 进 | 关注域 / 列表 | 1 产品 URL | 1 文章/文档 URL |
| 出 | 多条扫描卡片 | 分层情报 + 三态 | 单篇摘要 |
| 源 | PH 列表（或 paste） | WCC 抓页 | WCC 抓页 |
