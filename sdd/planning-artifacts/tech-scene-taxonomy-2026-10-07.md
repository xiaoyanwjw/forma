## 3. 可补充 Skill（候选项，未立项）

原则：和上面三个**不重复**；仍是「跑完有一页可带走」；产品侧偏「判断/扫描」，前沿侧偏「原文/材料」。

### 产品雷达 · 可补

| 候选 | 和早报/竞品的差别 | 为什么实用 |
|------|-------------------|------------|
| **发布会/发布页拆解** | 早报是多条扫描；这个是**一场发布**深拆 | 发布会后高频需求：新在哪、对谁有意义 |
| **品类地图** | 竞品是点对点；这个是**赛道俯瞰** | 「这个品类有谁、怎么分层」一页纸 |
| **评价炼金（科技）** | 不比官方卖点，炼**用户口碑** | 和应用商店/社区评价结合时很香；注意来源粘贴 |
| **定价与套餐对照** | 竞品偏定位话术；这个偏**买哪档** | SaaS/API 档位对照表，决策快 |

暂不补（易飘或和近端重叠）：无出处热点榜、绝对「值不值买」投资结论。

### 科技前沿 · 可补

| 候选 | 和链接速读的差别 | 为什么实用 |
|------|------------------|----------|
| **多链合读** | 速读是 1 链；这个是 **2～3 链合成一页** | 同一主题几篇官方文/博客，合成对照 |
| **长文精读卡** | 速读偏「快看懂」；这个偏**章节级要点 + 摘句** | 白皮书、长 RFC、长博客 |
| **材料对照** | 不是摘要一篇，而是**两份材料差异** | 新旧版本文档、两家技术方案对照 |
| **播客/纪要速读** | 输入是粘贴转录，不是网页链接 | 会议/播客听完没纪要时 |

暂不补：自动写代码、无原文编造摘要。

## 6. 市面参考（2026-10 调研）

目的：核对「产品雷达 / 科技前沿」拆法是否站得住；只学信息架构与输出纪律，不抄企业 CI 全套。

### 6.1 和近端 Skill 的对照

| 我们 | 市面常见叫法 | 代表产品 | 他们怎么切 |
|------|----------------|----------|------------|
| **产品早报** | Daily digest / Product radar / Briefing | [ToolRadarHQ](https://toolradarhq.com/)、[Launly](https://launly.com/)、开源 [AI Product Radar](https://github.com/BENZEMA216/ai-product-radar)、[OnAirToday](https://onairtoday.com/) | 「今天值得看的 3～7 条」；常按新品 / 更新 / 融资 / 工具分栏，不是一篇长文 |
| **竞品分析** | Competitive intelligence / Teardown | [Urlcomp](https://www.urlcomp.com/)（粘贴 URL → 分层报告）、[Discera](https://discera.ai/)、企业向 Klue / Crayon | 入口常是对手 URL / 对手列表；输出 battlecard、功能对照、变更监控 |
| **链接速读** | Link / article summarizer | [Cubox](https://cubox.cc/) AI Insight、[BibiGPT](https://bibigpt.co/) Article Summarizer、[Overchat Link Summarizer](https://overchat.ai/text/link-summarizer)、[Brevio](https://www.universalsummarizer.com/)、[Glasp](https://glasp.co/ai-summary)、Recall | **一篇材料 → 摘要 / 要点 / 追问**；偏阅读，不偏销售 battlecard |

结论：市面普遍把「扫市场」和「读一篇」拆开；我们两张卡与此对齐。

### 6.2 值得抄的信息架构

**早报类 → 产品早报**

- 条数要少（约 3～7），每条固定字段：**是什么 / 给谁 / 为什么现在看 / 出处**。
- ToolRadar、Launly 强调「几分钟读完」，不是情报库。
- OnAirToday 把 Daily Briefing 与 Product Radar（工具上新）分栏——近端可合成一个 Skill，但输出里最好能区分「动态」vs「新品」。

**竞品类 → 竞品分析**

- Urlcomp 最贴近 Forma：**公网 URL → 一页可审计报告**，字段标 Found / Inferred / Not Public——对齐「出处纪律」。
- Discera / Klue / Crayon 偏持续监控 + battlecard，近端不学成企业 CI；可学「对照表 + 可点开证据」。
- 国内实操常靠秘塔 / Kimi「深度研究」出结构化报告——用户要的是报告，不是聊天。

**速读类 → 链接速读**

- Cubox AI 常拆成：速读摘要 / 关键问答 / 自动划线——近端「一页摘要」够用；加厚时可参考「摘要 + 几个关键问题」。
- Brevio 分「每日多源合读」vs「单次 URL 速读」——正好对应产品早报 vs 链接速读的边界。
- 秘塔 / Perplexity 是搜索引擎，不是场景 Skill；可学「答案带引用」，不做通用搜索。

### 6.3 市面常见工作类型（与画廊对齐）

```text
监控扫描（Briefing / Radar）     → 产品雷达 · 产品早报
对手深挖（Competitor / Teardown） → 产品雷达 · 竞品分析
单篇消化（Summarize / Quick Read）→ 科技前沿 · 链接速读
```

企业情报（如 AlphaSense：研报/财报库）与 Forma 个人/小团队工作台不是一路，近端忽略。

### 6.4 市面有、近端先不做

| 市面常见加项 | 谁在做 | 对 Forma |
|--------------|--------|----------|
| 对手网站变更监控 | Discera、Crayon | 要爬虫+日程，后置 |
| 销售 Battlecard | Klue、Crayon | 偏 B2B 销售，场景弱相关 |
| 多源每日合读 | Brevio | 可作产品早报增强，不单开场景卡 |
| 视频/播客摘要 | BibiGPT、Recall、Cubox | 可作科技前沿后置 Skill（见 §3） |
| 知识库沉淀 | Recall、Cubox、Glasp | 与「跑完 Computer 一页纸」形态不同 |

### 6.5 落到近端 Skill 的三条原则

1. **产品早报**：学 ToolRadar / Launly——短条目 + 出处；不做 AlphaSense 式情报门户。  
2. **竞品分析**：学 Urlcomp——URL/粘贴 → 分层一页纸 + 可信度标记；不做 Klue 监控套件。  
3. **链接速读**：学 Cubox Quick Read——一篇进、一页出；与早报严格分开（早报多条扫描，速读单源深读）。
