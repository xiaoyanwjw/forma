# Forma 场景接入与打磨计划

**日期：** 2026-10-04  
**状态：** draft（产品计划，供按序落地）  
**阶段 0：** done（2026-10-04）— 五类筛选 + 科技「科技速读」/ 体育「装备选购对比」灰卡；本地库已 migrate + reseed  
**目标：** 画廊按「科技 / 电商 / 内容 / 体育 / 生活」分类；场景依次接入或打磨，每阶段都能演示「选场景 → 跑 Skill → Computer 审结果」。

---

## 1. 产品原则（做任何场景前先对齐）

1. **交付物优先**：每个场景必须有一份可带走的 Computer 成果（清单 / 报告 / 文案 / 脚本），不做真·自动发帖、改价、在线客服。
2. **一条主链做透**：同一分类里先打通「输入 → 主 Skill → 可选手递下一 Skill」，再开旁支。
3. **复用现有骨架**：新场景优先套用现成形态——清单卡（选品）、上架稿（Listing）、笔记体（种草）、对比/解读一页纸（科技）。
4. **灰卡可占位**：未做完的场景可以 `COMING_SOON` 亮相；正式开放前必须 Skill + view 模板 + 计费结算齐全。
5. **一次只深做一个新可用场景**：并行最多「1 个打磨中 + 1 个新接入」。

### 单个场景的「做完」定义

| 项 | 标准 |
|----|------|
| 画廊 | 有分类、标题、一句话说明；`AVAILABLE` 或诚实灰卡 |
| Skill | `SKILL.md` + 输出合同 + 示例 |
| Computer | Mustache view；可投影、可复制/带走 |
| 计费 | 仅可用成果落库后结算；失败不扣 |
| 冒烟 | 登录 → 进场景 → 跑通一次 → Computer 有结果 |

## 3. 分阶段路线（建议按此顺序推进）

> 节奏按「阶段」而非死板周数；每阶段结束应能对外演示一条完整路径。

### 阶段 0 — 画廊骨架（约 3～5 天）

**要做什么**

- 画廊一级分类：科技 / 电商 / 内容 / 体育 / 生活
- 现有卡归类：电商开店 → 电商；小红书种草 / 短视频 → 内容；周末行程 → 生活（出行）
- 科技 / 体育 / 生活先放灰卡占位（文案先写好）

**验收**

- 五个分类可筛或可浏览；灰卡点击仍是「即将推出」，不进假工作台

**不做**

- 不在本阶段开新 Skill

---

### 阶段 1 — 打磨现有两条主链（约 1～2 周）

**目标：** 演示不翻车，再扩新品。

| 顺序 | 工作 | 完成长相 |
|------|------|----------|
| 1.1 | 电商：选品 → Listing 手递 | 理由可读、手递按钮稳、Computer 版式干净 |
| 1.2 | 内容：选题 → 笔记 / 拆解 | 三胶囊路径顺、语气像真人分享 |
| 1.3 | 共用体验 | 空态提示、失败人话、积分提示一致 |

**验收**

- 两条路径各跑通 3 个真实输入样例；Computer 可直接复制带走

**出口标准：** 没有「半成品感」再开新场景。

---

### 阶段 2 — 第一波新可用场景（约 2～3 周，串行）

原则：**先复用、后开类**——优先接在现有场景旁，再开科技新类。

| 次序 | 场景 | 分类 | 为什么现在做 | 最小形态 |
|------|------|------|--------------|----------|
| **2.1** | 选题周报 | 内容 | 挂小红书旁，工具/体裁接近；好玩好分享 | 品类 + 受众 → 7 条选题卡 |
| **2.2** | 评价炼金 | 电商 | 强化 Listing；输入可粘贴评论，少依赖外爬 | 评论摘要 → 痛点/金句/改写建议 |
| **2.3** | 科技速读 | 科技 | 打开科技亮卡；详见科技专项计划 | 链接/粘贴 → 一页摘要 |

每做完一个：画廊 `AVAILABLE` → 冒烟 → 再开下一个。

---

### 阶段 3 — 填灰卡 + 垂类好玩（约 2～3 周）

| 次序 | 场景 | 分类 | 说明 |
|------|------|------|------|
| **3.1** | 短视频脚本 | 内容 | 填现有「短视频带货」灰卡；分镜+口播即可，不做剪辑 |
| **3.2** | 装备选购对比 | 体育 | 复用「解读/对比」一页纸；打开体育类 |
| **3.3** | 周末行程 | 生活（出行） | 填现有「周末行程」灰卡；一页行程，不做订票 |

**验收：** 五类各至少 1 张可用亮卡（体育/生活可与阶段 3 同步达成）。

---

### 阶段 4 — 加厚（有余力再做）

按「演示价值 / 复用成本」取舍，不必全做：

| 优先 | 场景 | 备注 |
|------|------|------|
| 高 | 选型说明书（科技） | 复用科技速读一页纸结构 |
| 高 | 竞品店铺拆解（电商） | 需更稳的信息源策略 |
| 中 | 趋势早报（科技） | 时效性要求高，注意「编造热点」风险 |
| 中 | 人设小传（内容） | 给笔记/脚本当前置 |
| 中 | 训练周计划（体育） | 好玩，合规注意「非医疗建议」 |
| 低 | 探店路线 / 出门清单 / 赛事看点 | 画廊丰富度；可后置 |

## 4. 每个新场景的标准作业（SOP）

1. **一句话价值**：谁、在什么情况、带走什么  
2. **输入最小集**：3 个以内必填（如品类 / 链接 / 粘贴文本）  
3. **输出合同**：字段表 + 假数据样例（`references/output.md`）  
4. **view 模板**：Mustache；先静态样例投影，再接 Agent  
5. **Skill 正文**：步骤、禁用项、何时不该用  
6. **种子与画廊**：`sceneCode`、分类、状态、排序  
7. **计费与历史**：结算点在可用 view 落库后  
8. **冒烟清单**：3 个好例 + 1 个坏例（空输入 / 超范围拉回）

---

## 5. 依赖与风险（产品侧）

| 风险 | 应对 |
|------|------|
| 外网抓取不稳（店铺/评论/热点） | 近端允许「用户粘贴原文」主路径；爬虫为增强 |
| 科技/体育「像胡说」 | Computer 标明需人工核实；解读侧重结构化，少给绝对结论 |
| 画廊卡片太多变乱 | 每类先 1 亮 + 若干灰；二级场景不要一次铺满 |
| 和旧 PRD 灰卡不一致 | 以本计划为准：生活=出行；旧「本地生活/套餐卖点」不再占生活位 |

---

## 6. 成功怎么看

| 阶段 | 成功信号 |
|------|----------|
| 阶段 0 | 五类画廊可读、可讲故事 |
| 阶段 1 | 内测用户愿复用电商或小红书路径，少抱怨「结果不能用」 |
| 阶段 2 | 三周内多 3 条可演示路径；科技有亮卡 |
| 阶段 3 | 五类都有至少 1 张真能跑的卡 |
| 整体 | 新场景接入不改首页信息架构（仍符合「画廊 → 工作台 → Computer」） |

---

## 7. 建议的「下一步立刻做」

1. 确认本计划阶段顺序（尤其 2.1→2.2→2.3）  
2. 开工 **阶段 0 画廊分类** + **阶段 1.1 电商打磨清单**（可并行：分类偏前端/种子，打磨偏 Skill/view）  
3. 阶段 2 启动时，先为 **选题周报** 写一页最小规格（输入 / 输出合同 / Computer 线框）
