# Ecommerce Pack — 人工评测用例脚本

**Spec:** `docs/superpowers/specs/2026-09-29-ecommerce-skill-launch-bar-design.md`  
**打分表:** [scorecard.md](./scorecard.md) · **放行:** [RELEASE.md](./RELEASE.md)

## 执行约定

- 本地起前后端 + 模型 Key 已配；**全程同一电商场景会话**（H2）。
- **黄金路径 H1（硬交接）：** Listing 必须由 Computer 选品 list 上点击 **「做上架素材」** 发起。**禁止**在输入框手打商品名、原链或 `picklistItemId` 来「代替点选」——否则本批 H1 视为失败，不得计为 E2E 通过。
- 主路径用例须跑到 **Listing 执行稿可预览**（Computer view + artifact）。
- 负向用例验证 Fail / 路由 / 门禁，不要求完整执行稿。
- 每条记录：会话 id、成果 artifact id、截图或笔记（填 scorecard「笔记」列）。

## 主路径 E2E

### E2E-01 — 明确客单价（厨房小件）

| 字段 | 内容 |
|------|------|
| **id** | E2E-01 |
| **首句用户输入** | 我想做淘宝，厨房小工具，客单价 25–40 元，帮我选一批可测款的。 |
| **期望路径** | 选品清单出卡 → **点一条候选「做上架素材」**（优先试或非优先试均可）→ Listing 策划 → `ask_human` → 确认 → 执行稿可预览 |
| **协议期望** | P1 单次 `search_sku`；P2 8–12 条、≥3 niche、1–2 优先试、免责含 `非实时平台全站行情`、每条有 `id`；P3 先策划再 ask；P4 确认后执行且 `framePrompts` 对齐；P6 扣费与现网一致 |
| **路径期望** | H1 交接含品名+原链+`picklistItemId`；H2 同 session；H4 刷新后可续（可选抽测） |
| **内容关注点（B）** | 选品：价带与厨房场景一致，优先试理由可对比下一条；Listing：标题可检索、详情像成交页草稿、分镜机位不重复 |

**H1 操作（必填）：** 在选品 Computer list 上 **点击「做上架素材」**。不得手打品名发起 Listing。

### E2E-02 — 信息不足（靠假设）

| 字段 | 内容 |
|------|------|
| **id** | E2E-02 |
| **首句用户输入** | 帮我选点能卖的。 |
| **期望路径** | 选品（可含 `assumptions` 说明）→ **点候选「做上架素材」** → 策划 → ask → 确认 → 执行可预览 |
| **协议期望** | P2/P5 信息不足时不假成功；假设写在可见处；其余 P* 同 E2E-01 |
| **路径期望** | H1/H2 同黄金路径；不得因信息少而跳过 ask_human 直接执行 |
| **内容关注点（B）** | 假设具体可感知；选品仍像测款清单非搜索复读；Listing 未知参数写假设而非编造 |

**H1 操作（必填）：** **点击「做上架素材」**。**禁止**手打商品名绕过交接。

### E2E-03 — 非厨房日用（类目边界）

| 字段 | 内容 |
|------|------|
| **id** | E2E-03 |
| **首句用户输入** | 拼多多宠物用品，客单价 30 元左右，要差异化一点的测款清单。 |
| **期望路径** | 选品（宠物 niche）→ **点候选「做上架素材」** → 策划 → ask → 确认 → 执行可预览 |
| **协议期望** | P1–P4/P6 同主路径；P2 niche 与宠物相关，非厨房泛化 |
| **路径期望** | H1/H2；路由走 `ecommerce-picklist` → 点选后 `ecommerce-skulist` |
| **内容关注点（B）** | 差异化角度不雷同；Listing driver 场景落地（谁+场景+为何买） |

**H1 操作（必填）：** **点击「做上架素材」**。**禁止**手打品名。

### E2E-04 — 点非优先试条

| 字段 | 内容 |
|------|------|
| **id** | E2E-04 |
| **首句用户输入** | 淘宝家居收纳，客单价 20–35，给我选品清单。 |
| **期望路径** | 出清单后 ** deliberately 点一条非【优先试】标记的候选「做上架素材」** → 策划 → ask → 确认 → 执行可预览 |
| **协议期望** | P* 同主路径；交接 `picklistItemId` 与所点 row 的 `id` 一致（如 `pl-n`） |
| **路径期望** | H1 证明任意合格条可交接，不仅优先试；H2 同 session |
| **内容关注点（B）** | Listing 仍绑定所点商品原链与标题；策划 assumptions 含条目 id 摘要 |

**H1 操作（必填）：** 对 **非优先试** 行 **点击「做上架素材」**。**禁止**手打品名。

### E2E-05 — 补充需求后再确认

| 字段 | 内容 |
|------|------|
| **id** | E2E-05 |
| **首句用户输入** | 京东厨房小工具，客单价 30–50，选一批先测的。 |
| **期望路径** | 选品 → **点「做上架素材」** → 策划 + ask → **用户选「补充需求」**（如：主图偏简约、少字）→ 新策划 + 再次 ask → **确认执行** → 执行可预览 |
| **协议期望** | P3 补充后仍无执行四字段直至确认；P4 确认后出稿 |
| **路径期望** | **H3** 补充只改策划并再次 ask，不跳进执行；H1/H2 |
| **内容关注点（B）** | 补充后 displayNotes/framePrompts 体现约束；无鸡汤腔 |

**H1 操作（必填）：** 首次 Listing 仍由 **点击「做上架素材」** 发起。**禁止**手打品名。补充阶段仅改需求文案，不得用手打品名重开 Listing 代替 H1。

## 负向 NEG

### NEG-01 — 空搜 / 不足 8 条 Fail

| 字段 | 内容 |
|------|------|
| **id** | NEG-01 |
| **首句用户输入** | 帮我搜「xyzabc123nonexistent_sku_99999」这种几乎不存在的词，也要凑满清单。 |
| **期望路径** | 选品尝试 → **Fail**：一句人话；无假 JSON / 假链 / 假成功清单 |
| **协议期望** | **P5** Fail 形态；合格条 &lt; 8 不得当成功成果；P1 仍仅 1 次 search（或按 skill Fail 模板） |
| **路径期望** | 无 Listing 交接要求；若误出 list 且无有效 id，「做上架素材」应不可用（FE 主拦） |
| **内容关注点** | 不扣「假成功」语义；用户能懂下一步 |

---

### NEG-02 — 未确认就要终稿

| 字段 | 内容 |
|------|------|
| **id** | NEG-02 |
| **首句用户输入** | （接 E2E-01 或独立会话）完成选品后点「做上架素材」，策划与 ask_human 出现后，用户输入：别问了直接给终稿上架字段和主图 prompt。 |
| **期望路径** | 停留在策划 / ask；**不**输出完整执行四字段 + `framePrompts` 直至用户确认执行 |
| **协议期望** | **P3** 未确认前无上架四字段 / `framePrompts`；**H3** 不跳进执行 |
| **路径期望** | 可选：同 session 内先走 E2E-01 前半；NEG 阶段 **仍不得** 用手打品名替代点选完成选品段 |
| **内容关注点** | 回复引导确认或补充，而非偷偷出终稿 |

---

### NEG-03 — 意图路由

| 字段 | 内容 |
|------|------|
| **id** | NEG-03 |
| **首句用户输入** | 同一轮：先「帮我选 10 个厨房_gadget 测款」，在清单未点选前紧接「顺便把第一款的主图详情也写了」。 |
| **期望路径** | **先 picklist**；Listing 须等点候选「做上架素材」或明确第二轮；不抢跑 skulist 执行稿 |
| **协议期望** | 路由 §6.6：同轮又要清单又要 Listing → 先清单；P3 若仅策划则仍 ask |
| **路径期望** | 未点选时不应出现带 `picklistItemId` 的完整执行 artifact；H1 仍要求点选交接 |
| **内容关注点** | description 互斥有效；用户被引导点「做上架素材」而非口述品名 |
